For your Azure Synapse Spark/Scala → Guidewire CDA S3 → Dedicated SQL Pool architecture, first confirm whether Guidewire supports private connectivity from an Azure-hosted workload and whether your Synapse Spark runtime can route to the relevant AWS endpoint. If that cannot be supported, use controlled HTTPS connectivity over the public endpoint, subject to Security Architect approval, rather than assuming that creating an AWS PrivateLink endpoint alone will enable the connection.

The Azure Synapse Spark/Scala jobs designed to ingest Guidewire Cloud CDA data from the Amazon S3 bucket cannot establish connectivity through a private link. The current connectivity arrangement does not support the required private network path between the Azure Synapse environment and the Guidewire-managed AWS S3 endpoint. As a result, the proposed integration will use HTTPS connectivity over the public internet, subject to confirmation that this access method is supported and approved by Guidewire and the relevant security teams. This is a change to the network connectivity design rather than a requirement to expose the S3 bucket publicly or weaken its access controls.

Internet-based connectivity can still be implemented securely through multiple layers of defence. All data transfers must use HTTPS with TLS 1.2 or higher, with certificate validation enabled to protect data in transit and prevent interception. Access to the S3 bucket should follow the principle of least privilege, using dedicated AWS IAM credentials or an approved cross-account role where supported, restricted to the specific bucket and required read operations. Credentials must be securely stored in Azure Key Vault, with access limited to the Synapse managed identity or an approved secret-retrieval mechanism, and must never be embedded in Scala notebooks, source code or logs. AWS S3 Block Public Access and appropriate bucket policies should remain enabled, ensuring that access is authenticated and authorised rather than anonymously available.

From a security architecture perspective, approval should be conditional on validating the end-to-end controls, including AWS-side restrictions on permitted access, credential rotation, Azure Key Vault access auditing, AWS CloudTrail logging, and monitoring of S3 access activity. Where supported by the Guidewire CDA service, access should be restricted to approved source egress IP addresses or other enforceable network controls, with the actual Synapse Spark outbound IP behaviour verified before implementation. The solution should also include security monitoring, incident response procedures and a documented assessment of the residual risks associated with public internet transport. The recommendation is to proceed with HTTPS-based internet connectivity as a controlled exception to private connectivity, subject to Security Architect approval and confirmation of the applicable Guidewire CDA access controls.
